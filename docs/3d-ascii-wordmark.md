# 3D ASCII wordmark

`assets/kj-wordmark.svg` is the name **KJ-AIML** extruded into a 3D slab,
rasterized to ASCII characters, behind a boot sequence: a status readout checks
itself off, colour-coded alert panels bury it, then "WELCOME / TO / MY / AI /
WORLD" each resolve and blow apart before a loading bar fills and detonates into
the wordmark, which then rocks on its vertical axis. One ~447 KB SVG, SMIL only,
no JavaScript, generated by
[`scripts/generate_wordmark.py`](../scripts/generate_wordmark.py).

Method follows the reference article credited in
[design-system.md](design-system.md); the text, palette, framing and font are
this profile's own.

## Why it is a flipbook

An SVG loaded through an `<img>` tag runs in restricted mode — no scripts, no
external resources, no interaction. It does run SMIL. Nothing can be rotated per
frame, so every frame that will ever be shown is rendered ahead of time and
declared. Twenty frames of a 91×20 character grid is about 36,000 characters of
text before gzip.

## Pipeline

| Stage | What happens |
| --- | --- |
| `build_shell()` | Draw the text with a bold TTF, threshold to a binary mask, extrude into a surface point cloud |
| `project()` | Rotate by yaw + tilt, back-face cull, perspective divide, Lambert shade + depth fog |
| `fit()` | One scale and offset that boxes every frame; derives the row count from the union bbox |
| `rasterize()` | Z-buffer splat into a `ROWS × COLS` character grid |
| `emit()` | Write the frames as SVG text rows, cycled by a discrete opacity animation |

Only the surface is ever visible, so a solid extrusion would be wasted work.
Three sets of points, each carrying an outward normal: front cap at `z = -0.6`,
back cap at `z = depth`, and side walls from boundary pixels repeated through the
depth, with the normal taken from which 4-neighbours are empty. No mesh library
and no triangles — points and normals are all a splatting rasterizer needs.

Brightness is Lambert against a fixed light times a depth-fog term, indexed into
the density ramp ``" .`:-=+*csS#%@"``. The z-buffer is one line, because painter's
algorithm is free when you can sort:

```python
order = np.argsort(-z)                     # far -> near, nearest wins
grid[row[order], col[order]] = idx[order]
```

## Shading twice over

`rasterize()` returns ramp indices rather than characters, because each cell's
index picks both its glyph *and* its colour. The ramp is already a dither, so it
also drives a four-step neutral scale — `#4a5058` → `#7d8590` → `#b1bac4` →
`#f0f6fc` — and the extrusion walls separate from the letter faces by value as
well as by density. At a 9px cell that second channel is most of what makes the
depth legible.

The bucket cuts come off the measured histogram, not an even split of the ramp.
The fixed light puts 79% of inked cells on indices 9 and 10 and nothing above 10,
so an even split leaves the brightest shade with zero cells and the art reads
flat. If `LIGHT`, `AMBIENT` or `FOG` ever move, re-measure before re-cutting —
histogram the inked indices across the frames and put each bucket boundary where
the cells actually are.

`emit()` writes one `<text>` per stretch of same-shade characters, with blanks
kept inside the current run rather than breaking it. Colour costs about 180 KB
over a flat fill (114 KB → 294 KB) because `s` and `S` interleave constantly and
fragment each row; the bucket *count* barely matters, so the file is no cheaper
at two shades than at four.

Each frame is a hidden `<g>` owning one `[i/n, (i+1)/n]` slice of the loop.
`calcMode="discrete"` snaps between values instead of interpolating, so frames
hard-cut instead of cross-fading.

## The intro

Before the loop starts, the panel plays a boot sequence once. Same constraint as
the flipbook — no scripting, so every phase is a declared keyframe.

| Phase | Ends at | What happens |
| --- | --- | --- |
| Status | 1.9s | Eight telemetry rows tick in between `\|` rules; each `[ ]` flips to a green `[x]` and its value appears a beat later, so the check reads as a result rather than decoration |
| Alert | 3.9s | Seven panels stack over the readout at ~0.18s apart, then the finished stack holds ~0.9s before clearing; the red `bad` ones pulse, the blue and amber ones sit still, so the alarm carries the eye instead of every panel competing |
| Clear | 4.2s | Both groups drop out |
| Words | 10.7s | Each word of `WORDS` resolves, holds `WORD_HOLD` seconds, and blows apart |
| Bar | 12.2s | The debris seats into a 64-segment loading bar that fills 0 → 100% |
| Burst → form | 13.5s | The bar detonates and the debris lands on the wordmark |

### Words share the 3D ASCII material; debris stays particles

The words were first spelled *out of* the particles, and they were hard to read.
At this size the dot grid affords only about **one dot per stroke** — Arial Bold's
stem is ~10px against a 9px `DOT_PITCH` — and the widest word needed 403 grid
cells against 260 particles, so roughly a third of every stroke was simply
missing. Raising the particle count to cover it would have pushed the file past
its size ceiling.

The intro now uses the same projected shell, lighting, fog, density ramp and
neutral shade buckets as the final mark. `WELCOME` and `WORLD` use the full
91-column form. `TO`, `MY`, and `AI` use centered 55-column grids constrained by
the final art height, so their cells stay the same size without clipping or
stretching. `WORD_HOLD` remains a straight readability knob (0.95s per word).

The particles still tie the sequence together. Each one converges on the word's
sampled cells, **fades out as the glyphs resolve**, and fades back in on the way
out — so the debris never competes with the word it just built, and the fact
that the sampled dot shape does not exactly match the rendered ASCII form is never
visible, because the particles are transparent at the moment they coincide.

### One particle set carries the whole show

Each of the 200 `<rect>`s gets a *single* `animateTransform` whose `values` walk
every station in order:

```
word 0 → scatter → word 1 → scatter → … → word N → bar seat → scatter → wordmark cell
```

Five words as five separate effects would cost five times the elements for the
same picture. The chain is why each particle stays one rect, and why adding a
word to `WORDS` costs keyframes rather than geometry. Both the transform and the
opacity track are built as `(time, value)` lists and normalised at the end, which
is what keeps ~40 keyframes per particle from becoming hand-counted `keyTimes`.

Scatter directions come off the golden angle (2.39996 rad × index) rather than an
RNG, so the debris fans evenly and the file stays byte-identical run to run — the
determinism test depends on that. Vertical throw is scaled by the panel aspect so
nothing flies past the viewport, where it would be clipped and read as a dropout
rather than as motion. Wordmark targets are an even stride through the inked
cells of the rest pose, so the debris lands spread across the whole word instead
of clumping in the dense areas.

### Cost

The intro runs ~13.5s before the loop starts, which is long for a README — most
visitors will not watch it out. That is the price of `WORD_HOLD = 0.95`; at the
original 0.38s the words were unreadable, so the length is deliberate. Every
duration is a constant at the top of the script.

The file is ~447 KB against the 500 KB ceiling `validate_profile.py` enforces,
about 19% headroom. Two things bought that back after the intro landed at 496 KB
with almost none:

- **Numeric precision.** Particle coordinates round to whole pixels (they are 4px
  squares — sub-pixel placement is invisible) and `keyTimes` to four decimals.
  The wordmark's `x` and `textLength` are exact multiples of `CELL_W`, so
  dropping their decimal is lossless. ~38 KB, no visual cost.
- **`PARTICLES` 260 → 200.** Once the words became text, particle count only
  affects burst density, where it barely reads. ~51 KB.

If it needs to come down further, dropping the flipbook from 20 frames to 16 is
the largest remaining saving and costs some smoothness in the rock.

## Why the constants are what they are

A character grid is an extremely low-resolution display and it punishes settings
that would be invisible at pixel resolution.

- **`COLS = 91`, the full 860px grid.** Seven characters at a readable cell size
  is what sets the panel width. Below ~12 columns per glyph the counters in `A`
  and the valley in `M` get narrower than the sideways offset the rotation gives
  the extrusion walls, the walls fill them, and the name rasterizes as one solid
  brick — at 490px wide it does exactly that. At 91 columns each glyph gets ~13,
  which is tight enough that `TRACKING` and `DEPTH_FRAC` also had to move.
- **`DEPTH_FRAC = 0.26`, `TRACKING = 0.20`.** The reference runs 0.34 depth on
  three letters. Seven need shallower walls: at 0.34 the extrusion closed `A`'s
  counter and filled `M`'s valley, and both glyphs came out as wedges. Trading a
  little depth for legible counters is the right way round — the side walls still
  carry the 3D read.
- **`front` sits at `z = -0.6`, not `0`.** The side walls also start at `z = 0`,
  so cap and wall points tie in the z-buffer and the letter faces come out
  streaked with wall-shaded pixels. Biasing the cap 0.6 mask-pixels proud makes
  it win every tie.
- **`CAM_DIST = 6.0`, `TILT_DEG = 4.0`, swing ±11°.** A closer camera projects
  the far letter ~20% smaller at the ends of the swing, which reads as a
  rendering fault rather than as depth. A steeper tilt slants the baseline across
  the word and the bottom row frays to a sliver. The extruded side walls carry
  the 3D read on their own.
- **Light keyed near the view axis** (`LIGHT = (-0.15, -0.45, -1.0)`).
  Conventional upper-left lighting makes the walls brighter than the letter faces
  and the glyphs dissolve into edge highlights. Keying toward the camera keeps
  faces solid and dense while walls fall away dimmer. That contrast gap is the
  3D read.

## Regenerating

The file is static — `generate_all.py` does not build it and the daily workflow
does not touch it, so CI never needs numpy or Pillow. Regenerate only when the
text, font or framing changes:

```bash
python -m pip install -r scripts/requirements-wordmark.txt
python scripts/generate_wordmark.py
```

Modes: `rock` (gentle oscillation, in use), `once` (one full turn then freeze),
`spin` (continuous turntable), `static` (frozen frame — also what `STATIC=1`
selects, matching the other generators). `--preview` prints frame 0 as text.

| Env var | Default | Purpose |
| --- | --- | --- |
| `WORDMARK_TEXT` | `KJ-AIML` | `\n` splits lines |
| `WORDMARK_FONT` | first found of Arial Bold / Verdana Bold / DejaVu Sans Bold | any TTF/TTC |
| `WORDMARK_FONT_INDEX` | `0` | face within a `.ttc` |
| `WORDMARK_TILT` | `4.0` | X tilt, degrees |
| `WORDMARK_COLS` | `91` | grid width; panel is `COLS × 9 + 36` px |
| `WORDMARK_ROW_MARGIN` | `4` | blank rows top and bottom |

Two sizing rules worth keeping:

- **Render at display size.** The panel is 855px wide and shown at 855px, so
  characters render ~1:1 at 9px. Rendering large and letting the browser scale it
  down softens the glyphs into mush.
- **`ROW_MARGIN` is the height knob.** `fit()` derives the row count from the art
  so the panel hugs it; the margin pads it back out.
